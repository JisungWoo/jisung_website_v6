HONEYWELL AEROSPACE / 데이터 엔지니어링

데이터 갱신 시간을 줄이기 위해
처리 구조를 개선했습니다.

조회에 몇 시간씩 걸리는 설계용 뷰를 분석하고, 처리 구조를 바꾸는 방안을 먼저 제안했습니다. 팀과 함께 중간 결과를 테이블에 저장하도록 파이프라인을 재구성했습니다.

Snowflake · SQL · 파이프라인 설계

처리 구조와 개선 과정 보기 ↗

개선 결과

전체 데이터 갱신 약 30분

여러 CTE와 서브쿼리, 수십 개의 조인이 얽힌 구조. 수백 개 컬럼과 1,000만 행이 넘는 데이터 모델을 다뤘습니다.

변환 단계 사이에 스테이징 테이블과 데이터 마트 테이블을 추가했습니다.

Snowflake 처리 구조 개선 자세히 보기+

실행 내역부터 확인합니다

설계용 뷰에 단순 SELECT를 실행해도 완료까지 2~3시간이 걸렸습니다. Snowflake Query History로 실행 내역을 확인하고, 여러 CTE와 서브쿼리, 수십 개의 조인이 얽힌 로직을 단계별로 살펴보며 오래 걸리는 부분을 좁혀 갔습니다.

SQL과 처리 구조를 함께 개선했습니다

필요한 데이터를 앞 단계에서 걸러낼 수 있도록 CTE와 WHERE 조건을 조정하고, SELECT * 대신 필요한 컬럼을 명시했습니다. 필요한 로직을 유지할 수 있는 경우에는 설계용 뷰 대신 데이터 모델이나 리포팅 뷰를 참조했습니다. 뷰와 스테이징 테이블을 추가하는 방안을 먼저 제안했고, 팀과 함께 중간 결과를 저장하는 구조로 변경했습니다.

단계가 늘어나는 대신 중간 결과를 저장합니다

변환 단계 사이에 테이블을 두면 중간 결과를 이후 단계에서 다시 사용할 수 있습니다. 저장 공간과 적재 작업이 추가되는 만큼, 데이터 아키텍트와 협의해 갱신 순서와 주기를 정했습니다. 적재 실패 시 재처리 방식은 이 사례에서 구체적으로 다루지 않습니다. CTE를 사용하는 것만으로 결과가 테이블에 저장되는 것은 아닙니다.

개선 후 전체 데이터 갱신은 약 30분에 완료됩니다. 변경 전후의 행 수를 비교하고 MINUS 쿼리로 결과의 차이를 확인했습니다. 코드의 처리 로직을 바꾼 뒤 검증할 때도 대기 시간이 줄었습니다. 실제 업무 경험을 바탕으로 기재한 결과이며, 기존 2~3시간은 SELECT 실행 시간이므로 전체 갱신 시간과 같은 조건으로 비교한 수치는 아닙니다.

중복이 발생하는 조인 관계를 찾아갑니다

구매 주문 레코드가 중복되는 문제에서는 관련 컬럼과 조인만 남겼습니다. 조인을 묶음 단위로 하나씩 제외하며 중복이 발생하는 관계를 좁혀, 팀이 함께 조사할 수 있는 작은 쿼리로 정리했습니다.

상급자에게 시연했으며, 아직 다른 팀에서 사용하고 있지는 않습니다. 현재는 우선순위가 높은 다른 업무로 인해 추가 개발을 보류하고 있습니다. 재현 가능한 정확도 평가 결과는 공개하지 않았습니다.

개발을 이끄는 방식

요구사항을 구체화하고,
팀이 구현할 수 있게 정리합니다.

현업 담당자와 요구사항을 확인하고, 데이터 아키텍트와 모델 설계를 검토합니다. 해외 개발팀이 QA·운영 데이터에 접근할 수 없어 해결하기 어려운 문제는 제가 직접 조사하고 수정합니다.

  1. 필요한 데이터와 계산 기준을 확인합니다

    비즈니스 담당자와 디렉터·시니어 디렉터에게 필요한 데이터와 계산 기준을 확인합니다. 모호한 조건을 구체화하고, 변경된 요구사항이 있는지 계속 확인하며 데이터 아키텍트와 모델에 반영할 방법을 검토합니다.

  2. 개발팀이 바로 이해할 수 있게 전달합니다

    해외 개발팀에는 구현 순서와 확인할 사항을 단계별로 전달합니다. 설명만으로 이해하기 어려운 부분은 그림, Excel 자료, 화면 캡처, 코드 예제를 함께 준비해 요구사항과 처리 로직을 같은 기준으로 이해할 수 있게 합니다.

  3. 접근 권한 때문에 막힌 문제는 직접 해결합니다

    해외 개발팀이 직접 확인할 수 없는 QA·운영 데이터는 제가 확인합니다. 중복 데이터나 복잡한 쿼리의 동작, 성능 문제를 조사하고 필요한 부분을 수정합니다. 조사 중 새로 확인할 조건이 생기면 관련 담당자와 다시 협의합니다.

지연된 프로젝트를 맡아 기한 내 운영 배포까지 마쳤습니다

진행이 지연된 장기 프로젝트에 중도 투입됐습니다. 원래 담당하던 업무는 아니었지만 책임을 맡아 디렉터와 현업 담당자에게 필요한 내용을 지속적으로 확인하며 개발과 QA를 진행했고, 기한 내 운영 배포까지 마쳤습니다. 진행 상황을 더 정확히 파악할 수 있도록 보고 방식의 개선 필요성도 제기했습니다. 현재는 AI로 진행 상황 공유를 자동화할 수 있을지 검토하고 있습니다.
